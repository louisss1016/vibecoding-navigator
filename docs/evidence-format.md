# 证据格式：什么算"亲眼验证过"

铁律 4 说"AI 说完成了不算数，必须有真实运行证据"。这个文件定义证据长什么样、放哪、怎么引用。没有按本格式留痕的验收，一律视为没验收。

## 目录结构

每个切片的证据放一个目录，用切片 ID 命名：

```
docs/evidence/
├── slice-03-cancel-button/
│   ├── verify-output.txt        # 验证命令的完整原始输出（贴全文，不许摘要）
│   ├── screenshot-list.png      # 关键 UI 状态截图
│   ├── screenshot-error.png     # 故障状态截图（对抗性审查时制造）
│   └── notes.md                 # 本轮四个问题的答案 + 五维评测记录
├── slice-04-...
└── gate-20260925-182000.txt     # scripts/gate.sh 自动落盘的门禁报告
```

## 三类证据的标准

### 1. 命令输出（verify-output.txt）

- **完整原始输出**，从命令行直接复制或重定向：`npm test > docs/evidence/<切片>/verify-output.txt 2>&1`
- 不许只贴"3 passed"这种摘要——要通过输出能看到：跑了哪些用例、每条的结果、耗时。
- 子 agent 回报时，五要素之二就是"验证命令 + 原始输出全文"，编排层负责落盘。

### 2. 截图（screenshot-*.png）

命名规则：`<状态>-<步骤>.png`，例如：

- `list-after-add.png`（主链路结果）
- `state-empty.png`（六种产品状态各一张）
- `chaos-offline.png`（故障制造者视角：断网时的人话错误）

截图要求：能看到关键 UI 状态（数据在不在、错误信息是不是人话），不是拍整个桌面。

### 3. 数据对账（notes.md 或对账截图）

涉及数字的（总额、条数、金额）：输入 N 条 → 显示值 = 手工算的值，把两边数字都写进 notes.md。

## notes.md 模板（每轮结束必填）

```markdown
# 切片 <ID>：<一句话定义>

## round-loop 四问
1. 这次改变了用户的什么行为：
2. 证据是什么：（引用本目录的文件名）
3. 还没解决什么：
4. 下一轮最小问题是什么：

## 五维评测
| 维度 | 结果 | 备注 |
|---|---|---|
| 结果 | ✅/⚠️/❌ | |
| 过程 | | |
| 证据 | | |
| 安全 | | |
| 成本 | | （启动/响应/内存实测值） |

## golden cases
- 新增/更新的 case id：
- tests/golden-cases.json 的 last_run 已更新：是/否
```

## AGENTS.md 怎么引用证据

AGENTS.md 的"已完成"列表里，每条切片附 commit hash + 证据目录路径：

```markdown
- [x] 切片3：取消按钮 → run_cancelled 事件（commit a3f2c1，证据 docs/evidence/slice-03/）
```

**路径，不是内容**——AGENTS.md 超过 200 行就没人看了，证据详情去目录里看。

## 常见错误

- 把证据贴在聊天记录里：聊天记录会丢、会刷走、AI 新对话看不到。release-gate 自己要求"已知限制不要埋在聊天记录里"，证据同理。
- 只贴通过的部分：失败的输出、警告、WARN 项更有信息量，对抗性审查的证据（截图-error.png）必须留。
- 截图拍整个桌面：关键信息被淹没，评审时等于没有。
- 子 agent 口头说"测试通过了"：没有落盘的原始输出 = 没测过，五要素缺项直接打回。
