# 切片纪律：让 AI 写代码不跑偏的 6 条规矩

## 1. 先读现状，再提方案

**不要一上来就让 AI 写代码。**

正确顺序：
```
"先读一下 src/api/ 里现有的代码结构，不要改任何东西。
读完告诉我：你打算改哪几个文件、每一步做什么、怎么验证。
我说"可以"之后你再动手。"
```

为什么：AI 不看现状就写，十有八九会重复造轮子或跟现有代码风格打架。

## 2. 最小纵向切片

一个切片 = 跨层但完整的一条小功能，不是"把前端全写完再写后端"。

✅ 好切片：
- 加一个 API 函数 `addTodo()` + 对应数据库调用 + 一个按钮触发它
- 从 UI 到 DB 全打通，但只做这一件事

❌ 坏切片：
- "把所有 API 层写出来"（太大）
- "先写 UI 组件，后端下次再说"（横切，跑不通）

判断标准：这个切片做完，你能亲手点一下看到效果吗？能就是好切片。

**好任务的五个特点**（写派工单前逐条核对，缺一条这个切片就还没准备好）：
1. **输入明确**——要改哪几个文件、参考哪个现有模式，写清楚了
2. **操作明确**——做什么、不做什么，边界划清了
3. **输出明确**——交付物是什么形态（函数/组件/文档），改哪些文件
4. **验收标准明确**——怎么算做完，最好是一条能跑的测试
5. **依赖明确**——前置条件是否就绪（契约已定、数据已备、权限已开）

## 3. 先写失败测试

切片开始时，先让 AI 写一个会失败的测试：

```
"先写一个测试：调用 addTodo() 后，数据库里应该有一条记录。
这个测试现在应该是失败的，因为 addTodo() 还没实现。
把这个失败的测试贴给我看。"
```

然后再写实现让它变绿。

为什么：测试就是这个切片的验收证据。不用你口头说"做完了"，测试绿了就是做完了。

## 4. 给参考文件，不要抽象描述

❌ 差的 prompt：
```
"写一个创建 todo 的 API"
```

✅ 好的 prompt：
```
"参考 src/api/notes.ts 里 createNote() 的写法，
照着同样的模式写 createTodo()，
输入是 { title: string }，返回 { id, title, createdAt }。"
```

为什么：给 AI 一个现有模式照抄，比描述十句抽象要求都管用。

## 5. 每次 prompt 都重申技术栈

新话题开始时，第一句永远是：

```
这是一个 React 18 + Vite + SQLite 项目。
代码在 src/ 下，API 在 src/api/，数据库访问在 src/db/。
先读 AGENTS.md 了解当前进度。
```

为什么：新话题 AI 不记得上一轮你说过什么。每次重申，防止它用错技术栈或找错文件。

## 6. 契约先行

跨层调用之前，先把接口定义清楚，再写实现。

```
"先定义 addTodo() 的输入输出类型：
  input: { title: string }
  output: Promise<{ id: number, title: string, createdAt: number }>
  error:  { ok: false, error: { code: string, message: string } }

这个类型定下来后，前端和后端各自实现，不要改类型。"
```

为什么：接口不定清楚，前端和后端各写各的，最后对接不上。

## 附：DoR / DoD 两张 checklist

**DoR（Definition of Ready，可以开工的门槛）**——派工单发出去之前逐条核对：

- [ ] 输入明确：涉及文件、参考模式、上下文都已给到
- [ ] 操作明确：做什么、不做什么，边界无歧义
- [ ] 输出明确：交付物形态与文件清单写清楚
- [ ] 验收标准明确：有一条能跑的测试或可观察的判据
- [ ] 依赖明确：契约、数据、权限、前置切片均已就绪
- [ ] 无未决问题：open question 已清零，不存在"做的时候再说"

**DoD（Definition of Done，可以收工的门槛）**——五要素回报交上来之后逐条核对：

- [ ] 验证命令的原始输出全文贴在回报里（不是"测试通过了"一句话）
- [ ] 证据已落盘到 `docs/evidence/`，路径可回溯
- [ ] 失败测试确实变绿，不是靠改测试迁就实现
- [ ] 自审结论写明了"改了什么、为什么这么改"
- [ ] 与契约/既有约定有出入的地方已显式标记，没有静默偏离

两条 checklist 的关系：DoR 管住"别急着派工"，DoD 管住"别急着合并"。任何一条不过，退回重做，不进入下一环。
