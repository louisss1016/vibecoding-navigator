# 技术选型：纠结时用双向钢人

用户说"随便""都行""你定"的时候，不要直接拍脑袋选。把每个候选方案的最强理由摆出来再定。

## 方法：双向钢人论证

对每个纠结的选型问题，两边都先说到最强，再选。

### 模板

```
选型问题：【React vs Vue / SQLite vs PostgreSQL / 自建 vs SaaS / ...】

A 方案最强理由：
- 适用条件：
- 最大收益：
- 最大风险：
- 最难回答的反对意见：

B 方案最强理由：
- 适用条件：
- 最大收益：
- 最大风险：
- 最难回答的反对意见：

真正的分歧点：【哪一个变量决定了选 A 还是选 B】
还需要问用户的问题：【只问一个最关键的】
```

## 常见选型问题速查

### 前端框架：React vs Vue vs 不用框架

| 信号 | 选哪个 |
|---|---|
| 用户/团队已经熟 React | React |
| 用户想快速出页面、不想学新概念 | Vue |
| 项目就是几个静态页面或表单 | 不用框架，原生 HTML + 一点 JS |
| 需要复杂交互、状态管理 | React |

**MVP 阶段默认**：除非用户明确会某个框架，否则选他已经会的那个，不要学新的。

### 数据库：文件 vs SQLite vs PostgreSQL

| 数据量/查询复杂度 | 选哪个 |
|---|---|
| 就存几条记录，不需要查 | JSON 文件 |
| 单用户、本地、简单查询 | SQLite |
| 多用户、复杂查询、需要并发 | PostgreSQL |

**MVP 阶段默认**：SQLite。文件数据库够简单，后面真要换 PostgreSQL 再迁，不要一开始就上重的。

### 部署：本地 vs Vercel/Netlify vs 自己服务器

| 信号 | 选哪个 |
|---|---|
| 桌面应用、要读本地文件 | Electron / Tauri |
| 静态网站或前后端分离 Web 应用 | Vercel / Netlify |
| 有长期运行的后端任务、要自定义环境 | 自己 VPS |

**MVP 阶段默认**：选最省事的那个。本地能跑通就先本地，不要为了"上线"花一周搞部署。

### 自建 vs 用现成 SaaS

| 信号 | 选哪个 |
|---|---|
| 这个功能不是你产品的核心 | 用 SaaS |
| 这个功能错了会直接影响用户信任 | 自建（支付/权限/核心数据） |
| 你不确定用户要不要 | 先 SaaS 或 Mock，别自建 |

**MVP 阶段默认**：能 SaaS 就 SaaS。自建一个登录系统能花你一周，但 Clerk/Auth0 十分钟接上。

## Agent 项目选型速查

项目要接 LLM 时的四个高频选型，默认答案如下（详细契约见 `specialists/agent-architecture/SKILL.md`）：

### 知识从哪来：上下文 vs RAG vs 知识库

| 信号 | 选哪个 |
|---|---|
| 信息量小、任务相关、一次用完 | 直接进上下文 |
| 大量资料里动态召回相关片段（SOP/FAQ/历史案例） | RAG |
| 项目文档/代码说明需要结构化导航和引用 | 知识库/知识地图 |
| 实时精确查询（库存、价格、状态） | Tool/API，不用 RAG |

### 能力入口：Tool Calling vs MCP vs CLI

| 信号 | 选哪个 |
|---|---|
| 一次性函数/查询/计算 | Tool Calling |
| 企业系统、远程服务、跨客户端复用、要治理 | MCP |
| 本地成熟工具链（搜索/Git/测试/构建/批处理） | CLI |

### 单 Agent vs 多 Agent

**默认顺序不许跳级**：单 Agent + Tool → + Skill → + Workflow → Router + Worker → Synthesizer + Critic。

只有出现真实失效信号才升级：自审流于形式（上 Critic）、天然可并行子任务（上 Router+Worker）、需要隔离工具权限、单上下文超预算。简单任务上多 Agent = 把混乱复制 N 份。

### 模型：一个打天下 vs 路由

| 信号 | 选哪个 |
|---|---|
| MVP、单场景、量小 | 一个主力模型打天下 |
| 有明确廉价子任务（分类/路由/摘要） | 小模型做杂活，大模型做最终生成 |
| 多供应商容灾/合规要求 | Provider Adapter + 路由 + 降级链 |

**MVP 阶段默认**：单 Agent + 一个模型 + Mock 数据跑通主链路，别一上来就搭评测平台和多 Agent 架构。

## 选型完成后

把结论写进 `PROJECT.md` 的"技术栈"section，格式：

```
前端：React 18 + Vite
后端：Node.js + Express
数据库：SQLite
部署：本地 Electron
为什么这样选：[一句话理由]
备选方案：[如果以后要换，换什么]
```

不要选完就忘——把"为什么选这个"写下来，半年后你会感谢自己。
