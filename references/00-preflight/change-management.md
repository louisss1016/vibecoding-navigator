# 需求变更管理：中途想法变了怎么办

规划不是锁死的，但也不是随便改的。每次变更都要走评估，不要直接改代码。

## 变更影响分析七维

一个变更请求进来，不是"评估一下"这种感觉性动作，按七个维度逐个过一遍，再决定批准与否：

| 维度 | 要回答的问题 |
|---|---|
| **Scope（范围）** | 加/删了什么功能，哪些已做模块要作废 |
| **Schedule（进度）** | 影响哪些里程碑，计划怎么重排 |
| **Cost（成本）** | 额外工时、token/API 开销、要不要加资源 |
| **Architecture（架构）** | 要不要改技术栈、数据模型、模块边界 |
| **Test（测试）** | 哪些 golden cases 要重跑，要不要补迁移验证用例 |
| **Deployment（部署）** | 影响上线方式吗，要不要数据迁移、切换演练 |
| **Acceptance（验收）** | 验收标准变了吗，谁重新确认 |

七维都过完，写进 PROJECT.md 的变更记录（格式见下文），再动手。跳过七维直接改代码，项目就会进入"范围无限膨胀 → 时间失控 → 技术债增加 → 测试不足 → 上线延期 → 用户仍不满意"的下滑螺旋。

## 变更评估三问

收到用户新需求时，先问这三个问题，再动手：

### 1. 这影响哪一层？

| 影响层 | 例子 | 改什么 |
|---|---|---|
| 目标变了 | 本来做笔记，现在要做日历 | 回到前期重新走一遍 preflight |
| 范围变了 | 本来不要登录，现在要了 | 改 PROJECT.md，评估已做模块哪些要废弃 |
| 架构变了 | 本来用文件存储，现在要上云 | 改 ARCHITECTURE.md，评估迁移成本 |
| 只是实现变了 | 按钮颜色换一下 | 走正常切片流程，不算变更 |

### 2. 之前做的哪些要作废？

不要直接加新功能就完事。问：
- 已经写的代码里，哪些是因为旧需求存在的？
- 这些代码是删了、留着备用、还是改成新用途？
- 数据库 schema 要迁移吗？
- AGENTS.md 里的"已完成"记录要标记哪些作废？

### 3. 要不要回退到某个 commit？

如果变更很大，比如"砍掉登录模块"，可能之前围绕登录写的代码都要删。这时候：
- 不要在当前分支上硬删硬改——先 `git log` 找到"砍掉前最后一个验证通过的 commit"
- 从那个 commit 开新分支，或者直接 reset
- 在 AGENTS.md 里记下回退点

## 变更影响分析：重跑范围映射表（机械化，不靠感觉）

变更落地后，按类型确定必须重跑的 golden cases（`tests/golden-cases.json` 按 category 过滤）和必须复核的文档：

| 变更类型 | 必跑 golden case 分类 | 必跑自动门禁 | 必复核文档 |
|---|---|---|---|
| 目标变了 | **全部** | gate.sh 全量 | PROJECT.md 重写、ARCHITECTURE.md、AGENTS.md |
| 范围变了（加/删功能模块） | 相关分类 + state + data | gate.sh 全量 | PROJECT.md、AGENTS.md"已废弃" |
| 架构变了（换栈/换库/拆分） | **全部** + 新增迁移验证 case | gate.sh 全量 + 老数据升级冒烟 | ARCHITECTURE.md、PROJECT.md"已锁定决策" |
| 数据模型变了（schema/字段） | data + 主链路 + 重启恢复 | gate.sh + 迁移脚本验证 + 备份恢复演练 | ARCHITECTURE.md、RECON.md（存量项目） |
| 只改实现（换库函数/内部重构） | 主链路 + 相关分类 | gate.sh | 无需（commit message 说明即可） |
| 修 bug | 该 bug 的复现 case（必须已存在，不存在就补） | gate.sh | AGENTS.md |

规则：**新增的 golden case 先于修复落地**——修 bug 前，复现用例应该先是红的（slice-discipline 第 3 条：先写失败测试）。

## 变更记录格式

变更不要直接改 PROJECT.md 的正文，而是在末尾追加一条记录：

```markdown
## 变更记录

### v1 — 2026-09-25
- 初始规划
- MVP 主链路：打开 app → 写一句话 → 关掉再打开还在
- 技术栈：React + SQLite + Electron

### v2 — 2026-09-27
- 变更：用户说不需要本地桌面，要 Web 版
- 影响：
  - Electron 壳作废，改成纯 Web
  - SQLite 保留，前端从 Electron 改成浏览器访问
  - 已做的 IPC 层全删
- 仍可用：核心存储逻辑、React 组件
- 回退点：commit a3f2c1（Electron 版最后一次验证通过）
- 新决策理由：用户主要在手机上用，桌面端不是刚需
- 重跑范围：golden cases 全部 + 老数据升级冒烟
```

## 什么时候算"小变更"不用走流程

以下情况直接做，不用走变更评估：
- 改个文案、调个颜色
- 修一个 bug
- 补一个已做功能的边界情况
- 优化性能

以下情况必须走流程：
- 加新功能模块
- 删已做的功能
- 换技术栈或数据库
- 改用户故事（目标用户变了）
- 影响 AGENTS.md 里"已完成"列表的

## 变更后必须做的事

1. 在 PROJECT.md 末尾追加变更记录
2. 更新 AGENTS.md 的"已完成"和"正在做"
3. 如果有作废模块，在 AGENTS.md 里标记"以下模块已废弃"
4. 按上面的映射表重跑 golden cases，更新 `last_run`
5. commit message 写明"变更：xxx，原因：xxx，废弃：xxx，重跑：xxx"
