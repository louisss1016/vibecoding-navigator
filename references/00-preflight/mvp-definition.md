# MVP 定义：第一版到底做什么

## 核心原则

**第一版只做一条端到端链路**：用户从打开 app 到完成核心动作，中间不超过 3 步。

其他所有功能都是 v2 的事。

## 怎么找这条链路

问自己：

> "如果我只能让用户完成一件事，做完他就会觉得'这东西有用'，是哪件事？"

举几个例子：

| 项目类型 | MVP 链路 | 不是 MVP |
|---|---|---|
| 笔记 app | 打开 → 写一句话 → 关掉，下次打开还在 | 富文本、标签、搜索、同步 |
| 待办 app | 加一件事 → 划掉 → 划掉的不显示 | 截止日期、提醒、协作 |
| 记账 app | 记一笔花了多少 → 看今天总共花了多少 | 图表、预算、分类分析 |
| 聊天 app | 两个人在同一网络发消息能收到 | 图片、历史记录、多端同步 |

## 必答的三个问题

### 1. 第一版跑通哪条主链路？

写成一句话：

```
用户 [动作A] → 系统 [反应B] → 用户 [看到/得到C] → 他因此 [完成了D]
```

例：`用户输入一笔支出金额 → 系统存下来 → 用户切到"今日"tab 看到总额 → 他因此知道今天花了多少`

### 2. 什么叫"能交差"？

列出 3-5 条具体的、可观察的完成标准。不要写"界面好看""体验流畅"这种虚词。

✅ 好的验收：
- 输入金额后关掉 app，再打开数据还在
- 断网时 app 不白屏，提示"网络不可用"
- 连续输入 10 笔，总额正确累加

❌ 坏的验收：
- 用户体验好
- 界面美观
- 功能完整

### 3. 第一版明确不做什么？

列一个"不做清单"，越具体越好。这个清单在 coding 过程中是硬约束——AI 想做这些的时候直接拒绝。

例：
- 不做用户注册登录
- 不做云同步
- 不做图表和统计
- 不做深色模式
- 不做导出功能

## 第一版的技术选择原则

- **能用文件就别上数据库**（除非数据真的要查）
- **能用一个进程就别拆服务**
- **能用现成库就别自己造**（但要选最主流的那个，不选最酷的）
- **先跑通再优化**——第一版慢、丑、笨没关系，能跑通主链路就行

## 输出

把这一节的三个答案填进 `PROJECT.md` 的"MVP 主链路"、"验收标准"、"不做清单"三个 section。
